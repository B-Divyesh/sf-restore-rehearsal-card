Four declared stages

How it works

The manifest names each operation. The card records the result of each stage.

  1. 01

    Hash the backup

    Record its SHA-256 checksum and byte count. Do not put backup contents in the card.

  2. 02

    Check target isolation

    Refuse host namespaces, bind mounts, external resources, added capabilities, devices, published ports, and privileged services.

  3. 03

    Run declared checks

    Check container health, row-count ranges, and command exit codes.

  4. 04

    Write the signed card

    Record timings, checks, the RTO result, and an Ed25519 signature in Markdown.

One local binary

Install and run the CLI

Requires Docker Compose. The CLI itself never phones home.

● ● ●restore-rehearsal.toml
$ cargo install --git https://github.com/B-Divyesh/sf-restore-rehearsal-card
$ rrc init
$ rrc run --confirm-target restore-card-weekly --output weekly.md

Failed checks

Catch restore failures before an incident

A failed command, health check, row count, or RTO writes a signed failed card. The CLI exits 4 and still runs cleanup.

Product limits

What the CLI does not do

Bring your own backup, Docker context, and non-production credentials. The CLI does not call provider APIs.
